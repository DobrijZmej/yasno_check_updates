# YASNO Check Updates Bot

Бот для перевірки електроживлення по одній з груп по місту Київу. Відстежує зміни в розкладі відключень від YASNO та надсилає сповіщення в Telegram.

## Функціонал

- 🔍 Моніторинг змін розкладу для групи `8.1`
- 📡 **Уніфіковане джерело**: графіки YASNO/DTEK та режими DTEK/YASNO/Укренерго
- 🔀 **Ручне переключення**: старі API викликаються лише з `SCHEDULE_SOURCE=legacy`
- �📱 Автоматичні сповіщення в Telegram з вказанням джерела оновлення
- 🌐 Інтеграція із зовнішніми API для синхронізації даних
- ⏰ Попередження про відключення та відновлення електроенергії
- 📋 Консолідація перекриваючихся періодів відключень
- ⏱️ Відображення тривалості кожного періоду відключення
- 🏷️ Підтримка нової системи з 60 гупами DTEK
- 📁 Ротаційне логування з налаштовуваними розмірами файлів
- 🔄 Підтримка кросс-день періодів (відключення, що тривають до наступного дня)

## Встановлення

1. Клонуйте репозиторій:
```bash
git clone https://github.com/DobrijZmej/yasno_check_updates.git
cd yasno_check_updates
```

2. Встановіть залежності:
```bash
pip install -r requirements.txt
```

3. Налаштуйте конфігурацію:
```bash
cp .env.example .env
```

Відредагуйте `.env` файл та вкажіть ваші параметри:
- `BOT_TOKEN` - токен вашого Telegram бота
- `CHAT_ID` - ID чату для надсилання повідомлень
- `CITY` - місто (за замовчуванням: kiev)
- `GROUP` - номер групи відключень
- Інші налаштування логування та інтервалів

## Запуск

```bash
python main.py
```

Бот запуститься та буде перевіряти зміни в розкладі кожні 58 секунд (або згідно з налаштуванням `CHECK_INTERVAL`).

## Налаштування

Всі налаштування знаходяться в `.env` файлі:

| Параметр | Опис | Значення за замовчуванням |
|----------|------|---------------------------|
| `SCHEDULE_SOURCE` | Ручний вибір джерела: `unified` або `legacy` | unified |
| `SVITLO_MONITOR_URL` | Єдине джерело графіків і режимів | https://kit.uca.co.ua/svitlo_monitor_response.json |
| `YASNO_URL` | Старе YASNO API, лише для `legacy` | задано в `.env.example` |
| `DTEK_URL` | Старе DTEK API, лише для `legacy` | задано в `.env.example` |
| `ENABLE_MODE_NOTIFICATIONS` | Сповіщення про зміни режимів | true |
| `BOT_TOKEN` | Токен Telegram бота | Обов'язковий параметр |
| `CHAT_ID` | ID чату Telegram | Обов'язковий параметр |
| `ADDITIONAL_CHAT_IDS` | Додаткові ID чатів (через кому) | Необов'язковий параметр |
| `CITY` | Місто (не використовується) | kiev |
| `GROUP` | Група відключень | 8.1 |
| `LOG_LEVEL` | Рівень логування | INFO |
| `LOG_FILE` | Файл для логів | yasno_bot.log |
| `LOG_MAX_SIZE` | Максимальний розмір лог-файлу (МБ) | 10 |
| `LOG_BACKUP_COUNT` | Кількість резервних лог-файлів | 5 |
| `CHECK_INTERVAL` | Інтервал перевірки (секунди) | 58 |
| `EXTERNAL_API_URL` | URL зовнішнього API (необов'язково) | - |
| `EXTERNAL_API_TOKEN` | Bearer токен для API (необов'язково) | - |

## Уніфіковане джерело

Розклади YASNO та DTEK завантажуються з одного агрегованого endpoint-а. Режимні переходи беруться з історії DTEK, YASNO й Укренерго. Після першого запуску бот сповіщає про нові переходи та показує:

- короткий заголовок з емодзі відповідно до нового режиму;
- попередній і новий режим;
- скільки тривала минула зміна;
- офіційний коментар ДТЕК з `message` або `raw_status`.

Endpoint зберігає до десяти останніх змін на джерело, тому локальна статистика починається з історії, доступної під час першого запуску, і доповнюється новими переходами. Дані з `stale` або `error` не використовуються для режимних сповіщень. Стан курсорів і тривалостей зберігається локально у `states.json`.

Старі YASNO/DTEK loaders залишені в коді, але автоматичного fallback немає. Для ручного повернення встановіть `SCHEDULE_SOURCE=legacy` та перезапустіть бота.

Аварійні сповіщення та їхні джерела залишаються окремими й у цій інтеграції не змінюються.

## Інтеграція із зовнішніми API

Бот підтримує автоматичну синхронізацію даних із зовнішніми системами. При виявленні змін у розкладі дані автоматично відправляються на вказаний API endpoint.

### Налаштування

Додайте в `.env` файл:

```env
EXTERNAL_API_URL=https://your-api.example.com/api/update/schedule
EXTERNAL_API_TOKEN=your_bearer_token_here
```

### Формат даних

Дані відправляються POST запитом для кожного дня окремо:

```json
{
  "date": "2025-12-01T00:00:00+02:00",
  "group": "8.1",
  "slots": [
    {"start": 0, "end": 480, "type": "NotPlanned"},
    {"start": 480, "end": 600, "type": "Definite"},
    {"start": 600, "end": 1440, "type": "NotPlanned"}
  ],
  "status": "ScheduleApplies"
}
```

**Параметри:**
- `date` - дата у форматі ISO 8601
- `group` - номер групи відключень
- `slots` - масив слотів з часом (у хвилинах від початку дня) та типом:
  - `Definite` - планове відключення
  - `NotPlanned` - електроенергія наявна
- `status` - статус розкладу: `ScheduleApplies`, `WaitingForSchedule`, `NoOutages`

**Заголовки запиту:**
```
Authorization: Bearer {EXTERNAL_API_TOKEN}
Content-Type: application/json
```

## Логування

Бот використовує ротаційне логування з наступними особливостями:
- Логи записуються як в консоль, так і у файл
- Автоматична ротація файлів при досягненні максимального розміру
- Підтримка різних рівнів логування (DEBUG, INFO, WARNING, ERROR)
- UTF-8 кодування для коректного відображення українських символів

## Групи відключень

DTEK використовує 60 груп. Для цього екземпляра в `.env` встановлено `GROUP=8.1` і `USE_DYNAMIC_GROUP=false`.

## Створення Telegram бота

1. Знайдіть [@BotFather](https://t.me/botfather) в Telegram
2. Відправте команду `/newbot`
3. Вкажіть назву та username для бота
4. Отримайте токен та вкажіть його в `.env` файлі як `BOT_TOKEN`

## Отримання Chat ID

1. Додайте бота до чату або групи
2. Відправте будь-яке повідомлення боту
3. Перейдіть за посиланням: `https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getUpdates`
4. Знайдіть `chat.id` у відповіді та вкажіть його в `.env` файлі як `CHAT_ID`
